第 0 步 · 只读体检(什么都不动,先看清楚)
════════════════════════════════════════════════════════════════
# 0.1 有几个服务实例?——健康值 = 恰好 1 个
Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
  Where-Object { $_.CommandLine -like '*--svc-sinkhole*' } |
  Select-Object ProcessId, CreationDate

# 0.2 端口谁在听——80/443/53/28791 各 1 个;28792/28793 出现 = 多实例打架
foreach ($p in 53,80,443,28791,28792,28793) {
  $o = @(Get-NetTCPConnection -LocalPort $p -State Listen -ErrorAction SilentlyContinue)
  if ($o) { "port ${p}: PID " + (($o | ForEach-Object OwningProcess | Select-Object -Unique) -join ',') }
}

# 0.3 探活——这两条秒回 = 服务活的;超时 = 单实例卡死
try { "api=" + (Invoke-WebRequest 'http://127.0.0.1:28791/api/info' -UseBasicParsing -TimeoutSec 5).StatusCode }
catch { "28791 无响应(超时/未起)" }
try { Resolve-DnsName iflytek.com -Server 127.0.0.1 -Type A -QuickTimeout | Out-Null; "DNS 53=通" }
catch { "DNS 53 不通" }

# 0.4 任务指向哪个目录(装过多次会漂)
(schtasks /query /tn iflytek-sinkhole /xml) -match '<Command>|<Arguments>'

# 0.5 最近日志
Get-Content "$PWD\logs\sinkhole.log" -Tail 30
Get-Content "$PWD\logs\keepalive.log" -Tail 10

分诊表(症状 → 大概率原因 → 去第几步)
════════════════════════════════════════════════════════════════
设备打不开 iflytek.com                    → 端口没起/多实例/任务指错目录 → 1 → 2 → 4/5

53 被外部程序占                           → 第三方 DNS/代理             → 第 4 步
80/443 被占(IIS 等)                       → 设备走域名进不去            → 第 5 步

管理器按钮点了没反应                       → NO_PROXY 环境雷             → 第 7 步
开机后前几分钟服务不响应                   → Defender 冷扫描(正常)       → 等 5~8 分钟

第 1 步 · 【万能起手】单实例收敛(多实例/卡死/避让 都从这开始)
════════════════════════════════════════════════════════════════
# 1.1 收掉所有 --svc-sinkhole 实例(含卡死的、避让到 28792+ 的)
Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
  Where-Object { $_.CommandLine -like '*--svc-sinkhole*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
Start-Sleep 2

# 1.2 先停任务再起(必须"全杀完再跑",边跑边杀会又造双实例)
schtasks /end /tn iflytek-sinkhole
Start-Sleep 1
schtasks /run /tn iflytek-sinkhole

# 1.3 等就绪(冷启动 Defender 扫描期 5~8 分钟)
1..60 | ForEach-Object {
  Start-Sleep 5
  try { $r = Invoke-WebRequest 'http://127.0.0.1:28791/api/info' -UseBasicParsing -TimeoutSec 4
        if ($r.StatusCode -eq 200) { "OK 已就绪($([int]($_*5)) 秒)"; break } } catch {}
}

# 1.4 复查:实例必须=1,28792/28793 必须空
(Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
  Where-Object { $_.CommandLine -like '*--svc-sinkhole*' }).Count

第 4 步 · 53 被外部程序占用(DNS 端口不可替代,必须腾出来)

第 7 步 · 管理器按钮点了没反应(NO_PROXY 环境雷,已知坑)
════════════════════════════════════════════════════════════════
# 病因:环境里 NO_PROXY/no_proxy、HTTPS_PROXY/https_proxy 等"大小写双键"同时存在
# → PowerShell 5.1 给子进程建环境字典必抛 DuplicateKey → Start-Process -Redirect* 全炸
# (新管理器已内置去重;若你从被污染的终端手动跑脚本会撞)验证+临时修复:
$seen=@{}; $dups=@()
foreach ($k in @([Environment]::GetEnvironmentVariables('Process').Keys)) {
  $lk = ([string]$k).ToLowerInvariant()
  if ($seen.ContainsKey($lk)) { $dups += [string]$k } else { $seen[$lk] = [string]$k }
}
foreach ($d in $dups) { [Environment]::SetEnvironmentVariable($d, $null, 'Process') }
"已去重: $($dups -join ',')"    # 之后同一窗口里 Start-Process -Redirect* 即恢复
# 从桌面双击 管理器.exe 启动的不受影响(exe 里已自带此修复)
